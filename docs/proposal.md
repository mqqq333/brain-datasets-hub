# 脑数据集信息平台 · 方案草案 v0.3

日期：2026-11-14　作者：mqqq333　状态：评审后修订

评审：gpt-6-astra（high）与 gemini-4-argon（medium），见 docs/reviews/

## 1. 一句话定位

面向中国机构研究者、按版本逐条核实的脑数据集申请指南（信息层，不托管数据）。回答"这个数据集有什么、我能不能拿到、怎么申请、要多久、要花多少钱"。护城河在国内实操经验：哪个部门签字、人遗/伦理、真实排队时长、能否下载到本地。

## 2. 背景：现有产品调研（2026-11）

| 类型 | 代表 | 已做到 | 缺口 |
|---|---|---|---|
| 开放仓库 | OpenNeuro、DANDI、NEMAR、PhysioNet | 托管 + 搜索 | 只收录自己的、以开放数据为主 |
| 受控档案 | UK Biobank、ADNI/LONI、NDA、ABCD、HCP | 申请流程最细 | 各自为政、写在长文/PDF 里、经常变（ABCD 2025 年从 NDA 迁到 NBDC） |
| 联邦门户 | CONP（有 "How to get it" 筛选）、EBRAINS KG、DataLad、Google Dataset Search | 跨来源聚合 | "怎么获取"多为许可证字符串或外链 |
| 跨队列平台 | DPUK/NDP（痴呆队列跨队列比较 + 统一申请与报价）、GAAIN（跨队列发现）、AD Workbench | 跨队列发现与统一申请入口 | 面向自有队列，不覆盖中国机构申请实操 |
| 标准/工具/清单 | Neurobagel（访问类型、说明、入口等字段）、bci.report（EEG/BCI 清单、许可证溯源） | 访问字段与目录 | 不记费用、时长、资质、机构签字与国内流程 |
| 社区清单 | meagmohit/EEG-Datasets、awesome-bci、维基、知乎/CSDN 汇总 | 链接 + 被试数 | 链接目录，很多停更 |

因此"其他平台只给外链"不成立：已有平台提供跨队列比较、统一申请与访问类型字段。

关键信号：UK Biobank 从申请到拿数据的时间，2013 年约 69 周、2018 年约 24 周、现官方 FAQ 约 15 周——这类信息一直在变，值得持续追踪。注意官方平均值与历史数字计时起止口径不同，不可直接比较，也不能当作承诺。

## 3. 差异化

1. 中国研究者视角：按国内机构申请者实际会卡住的问题组织内容（签字部门、人遗/伦理、能否下载到本地、真实排队时长）。
2. 按渠道、按版本、逐字段附证据的申请要求，覆盖 fMRI/MRI/dMRI/PET/EEG/MEG/iEEG 等多模态；区分官方说明与用户实测。
3. 申请流程是一等公民：资格、协议、资质、费用、交付方式、用途与地域限制结构化，且落到"队列—版本—子集—渠道"的具体层级。
4. 可信度：关键字段带来源与核实日期，未知显式标注，过期字段降级显示。

## 4. 路线

- 第一阶段（本人建基座，零服务器成本）：
  - schema v0.1；约 15 个种子数据集，按申请路径（直接下载 / 注册 / 机构签字 / 付费 / 云内分析）覆盖挑选，并向中国研究者最常申请的数据集加权。
  - 站点：多维筛选（前端加载编译后的 datasets.json 驱动，Pagefind 仅做全文检索）+ 详情页 + 申请清单 + 无模型"需求筛选向导"；GitHub Pages + Cloudflare Pages 镜像（改善国内访问）。
  - 本地 LLM 辅助录入脚本生成 YAML 初稿，人工审核后入库；GitHub Issue Forms 作为反馈入口。
  - 字段级证据、按字段类型设复核周期、过期字段降级与变更记录，提前到本阶段。
  - 延后：完整双语（先中文 + 英文专有名词）、复杂对比、账号。
  - 验收标准：陪 5 位真实研究者完成一次"选数据—核资格—备材料—提交申请"判断，记录阻塞点写回指南；以是否正确判断、是否减少返工验收，而非收录条数或网站上线。
- 第二阶段（社区共建）：
  - GitHub Issue Forms → Actions 自动转 PR + 编辑审核：字段级投稿、附证据、显示差异；费用/资格变更需独立复核。贡献者认领数据集并署名。
  - 申请经历记录国家/机构类别/申请类别/各节点时间，含未获批与等待中，去标识化，避免只统计成功案例。
  - Git/YAML 仍为唯一数据源；只有出现真实协作瓶颈才引入数据库/服务器（"买服务器"不再是路线节点）。
  - 研究问题咨询助手放在本阶段：先用真实问题建评测集（不合格推荐率、引用支持度、拒答），再接模型（详见 7b）。
- 第三阶段：自动化变更检测——对公开页面做文本哈希比对，变化即发 Issue 人工复核；不做重爬虫。

## 5. 数据模型（每数据集一个 YAML；canonical 定义见 `schema/dataset.schema.json`）

- 层级：队列(dataset) → 发布版本(release) → 子集(subset：模态 + 原始/衍生数据) → 获取渠道(access channel)；费用与资格落到具体渠道。
- 基本：id、名称（中/英）、简介、机构、官网、DOI、引用方式、关联论文、模态、人群/疾病、样本量口径、格式、体量、附带数据。
- 获取是多维度、非互斥等级，逐渠道记录：注册 / 协议（click-through、DUA、MTA、签署方） / 资质（CITI 等） / 机构签字 / 伦理 / 费用 / 交付方式（本地下载 vs 仅云端） / 用途限制（GA4GH DUO codes） / 地域与数据出境限制 / 授权有效期与续期。
- 扫描/采集参数不做结构化，链接到协议原文；衍生品（如 fMRIPrep、FreeSurfer、连接矩阵）单独标注获取难度。
- 字段级溯源：关键字段带 `source_refs` + `as_of`；未知必须显式写 `unknown`，不以空值猜测。
- 时间：官方时长与用户实测分开，各自标明计时起止点，不混用比较。
- 复用标准：BIDS `dataset_description` + Neurobagel 访问键、GA4GH DUO、页面嵌 schema.org Dataset JSON-LD；DCAT 3 作为后续表达分发渠道的可选方案。

## 5b. 维护机制（第一阶段）

- 字段级证据与按字段类型的复核周期：费用/资格/流程较短，静态描述较长。
- 到期或超期字段在页面上明确降级为"待复核"，不再以可信面目呈现；变更记录由 git history 承载。
- 死链检查只证明链接可达，不足以证明条件有效；必须靠人工按周期逐条核实。

## 6. 种子数据集

约 15 个，按申请路径覆盖挑选（不按知名度或模态凑齐）；当前样例：UK Biobank、HCP Young Adult、CHCP。

待核实候选（尚未采纳）：dHCP、SRPBS、THINGS、Midnight Scan Club、NSRR（含 SHHS）、IMAGEN、PREVENT-AD、AIBL、TDBRAIN、Sleep-EDF、REST-meta-MDD、CHIMGEN、CCNP、ADNI、ABCD、TUH EEG。

## 7. 技术方案

- Astro 静态站 + Tailwind；Pagefind 仅做全文检索，多维筛选由前端加载编译后的精简 `datasets.json` 驱动；数据 `data/datasets/*.yaml`，以 `schema/dataset.schema.json` 做 JSON Schema 校验。
- GitHub Actions：schema 校验、死链与文本哈希检查、自动构建；GitHub Pages 托管 + Cloudflare Pages 镜像（国内访问）。
- Git/YAML 全周期为唯一数据源；暂不引入数据库/服务器。

## 7b. 研究问题咨询助手（第二阶段）

- 先经结构化检索/筛选得到候选，再交给模型，只在候选内推荐 2–3 个数据集并引用详情页；禁止凭记忆推荐库外数据集。
- 先用真实问题建评测集（不合格推荐率、引用支持度、拒答），达标后再接模型；模型可替换，免费额度不作为可靠性承诺。
- "可用人数"≠总样本量：须满足年龄/诊断/模态/质控交集，不得据总样本量推断可用性；无匹配时明确说"库中暂无"并引导提交建议。
- 默认不保存原始提问；设调用预算与停用开关；回答固定附"以官方为准"声明。

## 8. 风险

- 头号风险："页面看起来可信但关键条件已过期" → 字段级复核周期 + 过期降级"待复核" + git 变更记录；死链检查不够。
- 助手误推断风险：只引用本站仍可能误判资格与可用人数 → 评测集（不合格推荐率、引用支持度、拒答）+ 限候选内推荐 + 拒答与"以官方为准"。
- 与既有平台重复：差异化在中国研究者视角与按渠道/版本、附证据的核验深度，而非收录数量；数据开放可回馈上游。
- 准确性/法律：声明"以官方为准"；协议只链接或短引，不全文转载。
